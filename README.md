## GitHub Pages 部署（不需要建置）

1. 解壓縮完整 ZIP，將 `TruckSimulator-main/` **內部所有檔案及資料夾**上傳至目標 GitHub repository 的 `main` 分支根目錄；不要再套一層 `TruckSimulator-main/`。保留 `.nojekyll`（隱藏檔案）。
2. Repository → Settings → Pages → Build and deployment → Source 選擇 Deploy from a branch；Branch 選 `main`，資料夾選 `/ (root)`，Save。
3. 從 Pages 設定頁開啟 GitHub 顯示的正式網址（例如 `https://<帳號>.github.io/<repository>/`）。

- `index.html` 為裝置路由，`desktop.html` 為原桌機流程，`mobile/index.html` 為手機流程。由同一模板生成；可用 `?device=mobile` 或 `?device=desktop` 測試分流。三個入口與 `mobile/` 都必須完整部署。
- 入口已生成；不需 npm install、伺服器端程式、Cloudflare Worker 或自行新增 GitHub Actions。
- 保留所有原有功能、檔名及相對路徑，包括 `stage/`、`cabin/`、`systems/`、`nico/`、`youtube-player/`。
- Three.js 仍使用原版固定 0.152.2 的三個 HTTPS CDN 來源，須有網路及 WebGL。YouTube 播放依原服務的連線、嵌入授權及瀏覽器政策；HTTPS Pages 不需要本機 BAT，初次播放仍可能需要使用者操作。
- 本機原有 BAT 與直接開啟 HTML 的方式仍保留；本機 YouTube 播放請使用原 BAT。
- 保留原始碼、測試及開發工具。正式完整驗收的既有阻擋機制未變更。
- 公開部署前請確認有權公開專案中的真人影像與其他素材；Pages 上的靜態素材可被訪客取得。

1. 車輛與物理
鉸接運動：牽引車與拖車以前銷（鞍座）連接，倒車時拖車會依真實的運動關係擺動。
轉向：前輪最大轉角約 34°，方向盤會隨前輪轉角在畫面中轉動。
速度：前進最高約 25 km/h，倒車最高約 9.5 km/h；儀表盤刻度為 0–30 km/h。
換檔防呆：車輛還在動時不能直接反向換檔（會提示「請先煞停再切換方向」）；手煞車拉起時不能入檔（會提示「請先解除手煞車」）。
聯結角限制：牽引車與拖車夾角超過 76° 視為折刀，算一次碰撞。
碰撞：牽引車與拖車兩個車身都會偵測碰撞與場地邊界。碰撞累計 10 次 即車輛損壞、取消本關資格。
車體細節：牽引車雙後軸雙胎、轉向前軸；拖車三軸雙胎、支撐腳；貨櫃有肋條、門鎖桿與角柱；兩側有紅白反光條；大燈、遠光、煞車燈、倒車燈會隨操作反應。
停妥判定

車輛要同時符合下列條件，並維持靜止 1.2 秒，才算入庫成功：

項目	容許範圍
貨櫃尾端橫向偏差	±0.43 m
貨櫃尾端前後偏差	±0.6 m
貨櫃相對車位的角度	約 ±3.6°
牽引車與拖車夾角	約 ±6.9°
車速	小於 0.12 m/s

成功畫面會顯示用時與碰撞次數；零碰撞會特別標示。

3. 任務模式（實景關卡）

選關時可以自訂起訖與車頭方向：

進場：從道路出發，倒入隨機碼頭車位。
出場：從隨機碼頭出發，整台聯結車駛離並停入道路上 22 m × 4 m 的綠框內。
正向起始／反向起始：決定車頭或車尾朝向任務路線。
關卡	進場・正向	進場・反向	出場・正向	出場・反向
NS2	★★★★★★	★★★★★★	★★★★	不開放
NS5	★★★★★★	★★★★★★	★★★★★	★★★★★★
DC3	★★★★★	★★★★★★	★★	不開放

不開放的組合受限於碼頭空間，由核心直接擋下，不只是介面上不給點。

出場任務：先接貨櫃

出場任務一開始，牽引車與貨櫃是分開的：

切入 R 檔，對準貨櫃慢速倒車（銜接期間油門自動限制在 28%）。
儀表會顯示「銜接距離」，以及倒車銜接的目標貨櫃編號。
銜接條件：前銷到達貨櫃前銷位置、橫向偏差 ≤ 0.12 m、車頭方向偏差 ≤ 5°。
銜接成功後車輛暫停約 1 秒，提示「貨櫃銜接成功」，鬆開油門即可駛離。
如果在銜接前就離貨櫃太遠，會出現銜接警告。
出場停妥條件：牽引車與拖車的所有車角都在綠框內、車速 < 0.12 m/s、夾角 ≤ 約 6.9°、無碰撞。

5. 視野與觀察
探頭：左探最大 180°、右看最大 90°。按住 1／3 以每秒約 105° 轉動，也可以拖曳滑桿自由指定角度。左探時視點會穿過側窗探出車外，再往拖車方向看。
下車確認：車輛完全煞停後可以下車，繞到車外觀察貨櫃與障礙物（自動拉起手煞車，上車後需手動解除）。
四面後照鏡：左右各有一般鏡與廣角鏡，畫面是即時從場景擷取的真實視角。
每面鏡可獨立調整水平 ±28°、垂直 −22° 到 +32°。
可直接拖曳鏡片上的小方塊調整，也可以開啟精細調整面板；支援單鏡重設與四鏡重設。
調整需先煞停；角度會自動記憶，下次開啟仍保留。
鏡面拖曳方塊的大小可調整（12–48 px）。
俯視雷達：360° 俯視圖，顯示車身、障礙物、目標車位（車位在畫面外時會顯示指向箭頭）與 NICO 位置。
方向可切換「車頭固定」、「地圖固定」、「AUTO」；AUTO 會在前進時車頭固定、倒車時地圖固定。
近距離警報（一般模式）

車身與障礙物、場地邊界的距離小於 1.5 m 時，畫面邊緣出現紅色警示並發出嗶聲，顯示剩餘距離；距離越近，嗶聲越急促；小於 0.3 m 時顯示「危險・即將碰撞」。

6. 輔助與教學
NICO 引導員
在目標車位旁，以揮手動畫引導你倒車；揮手速度可調整（0.5×–1.5×）。
會自動避車：貨櫃接近時，NICO 會預測未來約 2.8 秒的車身軌跡，走到安全的位置避開。
按喇叭：牽引車距離 NICO 12 m 內按喇叭，NICO 會立刻讓位。
設定中有 NICO 預覽視窗，可以調整角度與速度。
教練示範
提供標準進場路線（實景關卡）的示範。播放前會先模擬整條路線，確認不碰撞、能停妥，才會開始。
速度 0.5×／1×／2×／4×，可暫停、重播、「同場自行練習」。
畫面會顯示教練目前的排檔、方向盤、油門與煞車，並有進度條。
其他任務組合（出場或反向起始）與基本訓練關卡尚無教練示範。
其他
儀表顯示：車速、檔位、聯結角（≥ 45° 變色警示）、後端距離、碰撞次數（7 次起變色警示）、用時。
內建新手操作導引（排檔 → 觀察 → 操作 → 入位）與各項功能說明卡。
一鍵重來；通關後可切換下一關（自動略過空地練習）。
7. 環境、天氣與燈光
時間：清晨／白天／傍晚／黑夜；運行方式可選「手動指定」、「每局隨機」、「同步台灣時間（UTC+8）」。
天氣：晴／陰／雨／每局隨機。下雨時有擋風玻璃雨滴與雨聲。
雨刷：關／慢／快三段，雨滴會隨雨刷掃過而被擦掉。
大燈：AUTO（依亮度自動開關）／ON／OFF；另有遠光燈。
夜晚與雨天會讓畫面變暗；路燈、碼頭燈、車燈光束與倒車燈會在地面形成光池。
右 A 柱掛著天氣卡片，隨時顯示目前的時間與天氣。
8. 個人化
車身與內裝改色：任選主色或套用 7 種預設色；內裝會自動跟著以較暗的色調搭配。可儲存，也可恢復預設。
畫質：AUTO／極高／高／均衡／省電／最低。
AUTO 會依即時 FPS 尋找符合門檻的最高畫質，門檻可在 8–30 FPS 間調整（預設 12）。
較低畫質會減少街景材質、樹木、機車、路燈與窗戶的數量，並降低後照鏡更新頻率與雨量；部分導航用的地標店面在所有畫質下都保留。
可在車艙顯示即時畫質與 FPS。
音效：引擎聲（隨車速與油門變化）、近距離警報、喇叭、雨聲，可一鍵靜音。
全螢幕。
9. 3D 駕駛艙
駕駛艙是 Three.js 立體模型，窗戶為真正的開口。
車門、方向盤、中控台上的按鍵都是實體 3D 按鈕，滑鼠移上去會顯示說明，長按會顯示提示：
車門：設定、選關、下車
方向盤：喇叭、車燈（顯示 AUTO／ON／OFF）、遠光、雨刷（顯示 OFF／LOW／HIGH）、模式
中控：俯視雷達開關、重來按鈕、YouTube 收音機、手煞車
排檔桿可直接拖曳到 D／N／R。
如果 WebGL 載入失敗或過慢，會出現啟動卡片，可選擇「重試 3D」或「改用 2D 駕駛艙」；WebGL 中途遺失時會自動降低解析度並嘗試恢復。
10. YouTube 車載音樂
車內收音機開啟音樂卡片，關閉卡片時音樂不中斷，播放中收音機螢幕會顯示頻譜動畫。
播放器功能：匯入 YouTube 播放清單、曲庫（歌曲／專輯／歌手／播放清單）、佇列、隨機播放、主題與背景圖片。
YouTube 需要 HTTP(S) 網址才能嵌入。直接以 file:// 開啟時會顯示說明，改用 GitHub Pages 或本機伺服器即可。

部署（GitHub Pages）

不需要建置。

將 TruckSimulator-main/ 內部所有檔案與資料夾上傳到 GitHub repository 的 main 分支根目錄，不要多包一層資料夾，並加入空白的 .nojekyll 檔案。
Repository → Settings → Pages → Source 選擇 Deploy from a branch，Branch 選 main、資料夾選 / (root)。
開啟 GitHub 顯示的網址即可。

需求：網路連線（Three.js 0.152.2 由 CDN 載入）與支援 WebGL 的瀏覽器；index.html、desktop.html、mobile/ 三個入口都必須完整部署。

開發者
入口 HTML 由 index.template.html 產生：修改原始碼後執行 node tools/build-entry.cjs，用 --check 驗證產物一致；請勿手動編輯產生的 HTML。
診斷：開發者工具中可呼叫 TruckRenderDiagnostics.snapshot() 取得渲染耗時；__simState() 取得唯讀的遊戲狀態。
新增實景關卡：
參照既有關卡建立新檔（如 stage/dc4.js），以 TruckRealScenes.register('dc4', ...) 註冊，名稱需與檔名一致、場景 id 不可重複。
在 stage/manifest.js 的 files 清單加入檔名；可設定 name 與 difficulty（1–6）。
必要介面：start、goal、obstacles、collision、parked、bounds、render；選用介面：randomize、info、coach、witness、signs、guide、turnMarkers、goalVisible、visualGoal。
上傳後重新整理即會出現在實景選單，不需修改 HTML。
